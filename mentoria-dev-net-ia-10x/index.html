O método que transforma a IA
em uma squad de seniores

A maioria falha porque usa IA como gerador de texto. Na mentoria, você aprende a usar IA como um processo de engenharia — com papéis definidos, etapas cronológicas e documentação gerada automaticamente.

① Product Manager → ② Arquiteto → ③ Planejador → ④ Coder → ⑤ Revisor
① Product Manager
Define o PRD

Requisitos, critérios de aceite e escopo do projeto. A IA não toca no código enquanto isso não estiver claro.

② Arquiteto
Desenha a arquitetura

Diagramas C4, ADRs e atributos de qualidade. Decisões arquiteturais documentadas antes de qualquer linha de código.

③ Planejador
Quebra o trabalho

Tarefas atômicas e sequenciais. Cada tarefa é pequena o suficiente para o agente executar sem perder contexto.

④ Coder
Escreve o código

Rastreando exatamente a tarefa e a arquitetura definida. Sem improvisar, sem fugir do escopo.

⑤ Revisor
Passa os checklists

Critérios de qualidade rigorosos antes de finalizar. Code review automatizado com os critérios que você definiu.

// arquitetura

Por que arquiteturas tradicionais
geram atrito com agentes de IA?

Não é que Clean Architecture seja errada — ela foi desenhada para times humanos, que carregam contexto na cabeça entre uma sessão e outra. O agente não carrega. Ele lê o que couber na janela de contexto e decide com isso. É aí que o atrito aparece.

Camadas tradicionaisLean Model Architecture (LMA)
Uma feature nasce espalhada entre Domain, Application, Infrastructure e APIA feature vive em um módulo, com seus próprios contratos
O agente precisa carregar quatro camadas no contexto para entender uma regraO agente carrega um módulo e já tem o contexto completo
Abstrações existem para inverter dependência entre camadasAbstrações existem quando há mais de uma implementação real
Uma mudança simples toca seis arquivos em quatro projetosUma mudança simples toca o módulo dela
Revisar o que o agente fez exige reler o projeto inteiroRevisar o que o agente fez cabe no diff de um módulo

Essa é uma tese técnica, não um dogma — e ela é demonstrada com código na semana 6, aplicada ao seu projeto. Você vai poder discordar com argumento, que é exatamente o ponto.

Perguntas frequentes

O que é o Lean Work SDD?

É o método desenvolvido na Leanwork que aplica rigor de engenharia de software no uso de IA agêntica. Em vez de mandar prompts soltos, você conduz a IA por um pipeline estruturado: PRD → Arquitetura → Planejamento → Código → Revisão.

Existe prova de que o método funciona?

Existe uma implementação pública. O Leanwork SDD Demo é um projeto .NET 10 construído inteiramente com o método, com 8 ADRs, 16 regras de negócio, 17 critérios de aceite, 12 tarefas, 14 reviews e 29 testes passando. Você pode clonar, rodar os testes e ler cada decisão antes de decidir.

O que significa o "10x" do nome?

Não é escrever 10x mais código nem uma promessa de produtividade garantida. É ampliar sua capacidade de transformar uma ideia em software: a IA executa, e você mantém o controle sobre arquitetura, regras de negócio, qualidade e decisões técnicas.

Precisa ser sênior para acompanhar?

Precisa ter o básico de C# e .NET. O público principal da mentoria são devs pleno e sênior, que já trabalham profissionalmente com o stack.
